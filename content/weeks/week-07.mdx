## Why prove anything?

Here is a formula that looks like a machine for making prime numbers:

$$
f(n) = n^2 + n + 41.
$$

Try it. $f(0) = 41$, prime. $f(1) = 43$, prime. $f(2) = 47$, prime. $f(3) = 53$, $f(4) = 61$, $f(5) = 71$: prime, prime, prime. Keep going and you will find a prime every single time, for forty values in a row. At that point almost anyone would be ready to bet that $f(n)$ is **always** prime. And almost anyone would lose the bet, because

$$
f(40) = 40^2 + 40 + 41 = 40 \cdot 41 + 41 = 41 \cdot 41 = 1681.
$$

Forty examples, and the claim is still false. This is the whole reason proofs exist. An example tells you that something is true **in one case**. A statement such as “$f(n)$ is prime for every $n$” talks about **infinitely many** cases, and no amount of checking can cover infinitely many cases. Only an argument can.

A good way to feel the difference is to think of a bridge. Nobody certifies a bridge by driving every possible truck across it. Engineers **calculate**: they show, from the laws of physics and the properties of steel, that any load up to a certain weight is safe. Testing a few trucks can reveal a weak bridge, but it can never show that a bridge is safe for all trucks. In mathematics, that calculation is called a **proof**.

> [!why] Why a software engineer should care
> Testing a program is checking examples: it can show that bugs are present, but never that they are absent. In 1994, Intel’s Pentium processor passed an enormous number of tests and still divided certain numbers incorrectly. The recall cost about 475 million dollars, and it is one of the reasons why chip makers, cloud companies and aircraft manufacturers now **prove** that critical parts of their systems are correct. Even when you are not writing formal proofs, proof thinking is what lets you say “this loop always terminates” or “this function never returns a negative number” and actually be right.

### A proof is a valid argument

Last week we built arguments line by line, with a rule of inference next to every line. A **proof** is exactly that: a valid argument whose premises are things we already accept, and whose conclusion is the statement we want to establish. The only difference this week is style. Instead of numbered tables, mathematicians write proofs in ordinary sentences. The sentences are still a chain of justified steps, and you should be able to point at any sentence and say **why** it follows from the ones before it.

So do not be fooled by the friendly prose: a proof is still a chain in which every link must hold. If one link is missing, the whole chain falls.

## The vocabulary of proofs

A handful of words come up again and again. The software analogies are not perfect, but they are a good way to remember the roles.

| Word | What it means | Think of it as |
|---|---|---|
| **Axiom** | A statement we accept without proof, the starting point. “For every integer $n$, $n + 0 = n$.” | the built-in rules of the language |
| **Definition** | The exact meaning of a word. “An integer $n$ is even if $n = 2k$ for some integer $k$.” | a type declaration |
| **Theorem** | A statement that has been proved. | a function that is finished and tested by proof |
| **Lemma** | A small theorem proved mainly to help prove a bigger one. | a helper function |
| **Corollary** | A statement that follows almost immediately from a theorem. | a one-line function that calls the big one |
| **Conjecture** | A statement believed to be true but not yet proved. It may turn out false. | an open issue |
| **Proof** | The argument that turns a conjecture into a theorem. | the code that closes the issue |

### The hidden “for all”

Mathematicians are a little lazy in how they state theorems. When a textbook says

> If $x > y$, where $x$ and $y$ are positive real numbers, then $x^2 > y^2$,

it really means

$$
\forall x\, \forall y\, \big( (x > 0 \land y > 0 \land x > y) \to x^2 > y^2 \big).
$$

The universal quantifier is invisible, but it is there, and it decides how the proof must start. To prove a statement about **every** $x$, we take an **arbitrary** $x$: a value we know nothing about except that it belongs to the domain. Think of it as a stranger whose name you don’t know. If you can prove the statement for this stranger, using nothing but the fact that they are in the domain, you have proved it for everyone, because the stranger could have been anyone. That is universal generalization from [week 6](/weeks/week-06).

A programmer already knows this idea. Testing `square(3)` checks one input. Reasoning about `square(x)` for a parameter `x`, without assuming anything about its value, covers all inputs at once.

## Our building blocks: definitions

Almost every proof in this course is built from definitions. Here are the ones we will use this week. Read them carefully; they are the bricks.

> [!definition] Even and odd
> An integer $n$ is **even** if there is an integer $k$ such that $n = 2k$.
> An integer $n$ is **odd** if there is an integer $k$ such that $n = 2k + 1$.
> Every integer is either even or odd, and no integer is both.

> [!definition] Divides
> For integers $a \neq 0$ and $b$, we say $a$ **divides** $b$, written $a \mid b$, if there is an integer $k$ such that $b = a k$. For example, $3 \mid 12$ because $12 = 3 \cdot 4$.

> [!definition] Rational and irrational
> A real number $r$ is **rational** if there are integers $a$ and $b$ with $b \neq 0$ such that $r = \dfrac{a}{b}$. A real number that is not rational is **irrational**.

Notice that every one of these definitions hides an **existential** quantifier: “there is an integer $k$ such that …”. This gives almost every proof the same three-part rhythm:

1. **Unpack.** Turn the words in the hypothesis into equations: “$n$ is odd” becomes “$n = 2k + 1$ for some integer $k$”.
2. **Work.** Do algebra or reasoning with those equations.
3. **Repack.** Arrange the result so that it matches a definition: if you can write a number as $2 \cdot (\text{an integer}) + 1$, you have shown that it is odd.

It is a little like a program that parses its input, processes it, and formats its output. If you ever get stuck at the start of a proof, the first thing to do is always the same: **write down the definitions** of the words in the statement.

## Proving “if p, then q”

Most theorems have the shape $p \to q$, or $\forall x\,(P(x) \to Q(x))$. Recall from [week 2](/weeks/week-02) that a conditional is false in only **one** row of its truth table: when $p$ is true and $q$ is false. So proving $p \to q$ means exactly one thing: **showing that this bad row can never happen.** Every technique below is a different way of ruling out that one row.

Two of these ways are almost too easy, but they do show up, especially in induction proofs later in the course.

- **Trivial proof.** If you can show that $q$ is true on its own, then $p \to q$ is true no matter what $p$ is. Example: “if $a \geq b$, then $a^0 \geq b^0$” is true because $a^0 = 1 = b^0$, whatever $a$ and $b$ are.
- **Vacuous proof.** If you can show that $p$ is false, then $p \to q$ is true no matter what $q$ says. Example: “every unicorn in this classroom is purple” is true, because there are no unicorns in this classroom, so there is no unicorn that could fail to be purple.

> [!note] Vacuous truth in Python
> Python agrees with logic here: `all([])` returns `True`. “Every element of the empty list is …” is vacuously true, because there is no element to break it. This is not a quirk of the language. It is the definition of $\forall$.

## Direct proof

A direct proof is the most natural thing in the world. You **assume $p$**, and you walk, step by step, until you arrive at $q$. Think of it as a road trip: $p$ is where you start, $q$ is where you want to be, and every sentence of the proof is one stretch of road that you are allowed to drive on (a definition, an axiom, algebra, or something already proved).

> [!tip] Recipe for a direct proof of p → q
> 1. Write “Assume $p$.”
> 2. Unpack $p$ with its definition.
> 3. Work towards the form that the definition of $q$ needs.
> 4. Write “Therefore $q$.”

### Example 1: the sum of two even numbers is even

**Theorem.** If $m$ and $n$ are even integers, then $m + n$ is even.

Before writing anything formal, it helps to do some **scratch work**, just as you would sketch on paper before you start coding. What do we know? $m$ is even, so $m = 2a$ for some integer $a$. $n$ is even, so $n = 2b$ for some integer $b$. What do we want? $m + n = 2 \cdot (\text{something})$. Then $m + n = 2a + 2b = 2(a + b)$, and $a + b$ is an integer. Done. Now we write it properly.

> [!proof]
> Let $m$ and $n$ be arbitrary even integers. By the definition of even, there are integers $a$ and $b$ such that $m = 2a$ and $n = 2b$. Then
> $$
> m + n = 2a + 2b = 2(a + b).
> $$
> Since $a + b$ is an integer (a sum of integers is an integer), $m + n$ is two times an integer. By the definition of even, $m + n$ is even.

> [!warning] Use a new letter for each new number
> A very common mistake is to write “$m = 2k$ and $n = 2k$”. That silently assumes $m = n$! The definition gives each even number **its own** $k$, so give each one its own letter: $a$, $b$, $k$, $l$, and so on.

### Example 2: the square of an odd number is odd

**Theorem.** If $n$ is an odd integer, then $n^2$ is odd.

**Scratch work.** We know $n = 2k + 1$. We want $n^2 = 2 \cdot (\text{integer}) + 1$. Let us just square it and see whether we can pull a factor of 2 out of everything except a final $+1$.

> [!proof]
> Let $n$ be an arbitrary odd integer. Then $n = 2k + 1$ for some integer $k$. Squaring both sides,
> $$
> n^2 = (2k + 1)^2 = 4k^2 + 4k + 1 = 2(2k^2 + 2k) + 1.
> $$
> Let $r = 2k^2 + 2k$; it is an integer, because products and sums of integers are integers. So $n^2 = 2r + 1$, and by the definition of odd, $n^2$ is odd.

Look at the shape of that proof: **unpack** ($n = 2k + 1$), **work** (square and factor), **repack** ($2r + 1$). You will see this rhythm dozens of times this semester.

### Example 3: the sum of two rational numbers is rational

**Theorem.** If $r$ and $s$ are rational numbers, then $r + s$ is rational.

> [!proof]
> Let $r$ and $s$ be arbitrary rational numbers. By definition there are integers $p, q, t, u$ with $q \neq 0$ and $u \neq 0$ such that $r = \dfrac{p}{q}$ and $s = \dfrac{t}{u}$. Adding the fractions,
> $$
> r + s = \frac{p}{q} + \frac{t}{u} = \frac{pu + qt}{qu}.
> $$
> Let $v = pu + qt$ and $w = qu$. Both are integers, and $w \neq 0$ because a product of two nonzero numbers is not zero. So $r + s = \dfrac{v}{w}$ with $w \neq 0$, which means that $r + s$ is rational.

Notice the small sentence “$w \neq 0$ because …”. It is easy to forget, and without it the proof is incomplete: the definition of rational **requires** a nonzero denominator. Checking every condition of the definition when you repack is part of the job.

### Example 4: divisibility is transitive

**Theorem.** For integers $a, b, c$ (with $a, b \neq 0$): if $a \mid b$ and $b \mid c$, then $a \mid c$.

> [!proof]
> Assume $a \mid b$ and $b \mid c$. Then $b = ak$ and $c = bl$ for some integers $k$ and $l$. Substituting the first equation into the second gives $c = (ak)l = a(kl)$. Since $kl$ is an integer, $a \mid c$.

Three lines, and we will use this fact again when we study number theory. Most useful lemmas are like this: short, and used everywhere.

## Proof by contraposition

Sometimes the front door is locked. You assume $p$, unpack it, and get stuck. Then it is time to try the **back door**.

From [week 3](/weeks/week-03) we know that a conditional is equivalent to its contrapositive:

$$
p \to q \;\equiv\; \neg q \to \neg p.
$$

“If it rained, the street is wet” says exactly the same as “if the street is dry, it did not rain”. So instead of proving $p \to q$, we may prove $\neg q \to \neg p$ **directly**: assume $\neg q$, and walk to $\neg p$. Same house, different door.

### Example 1: when the front door is locked

**Theorem.** If $n$ is an integer and $3n + 2$ is odd, then $n$ is odd.

Let us first try the front door, to see why it fails. Assume $3n + 2$ is odd, so $3n + 2 = 2k + 1$ for some integer $k$. Then $3n = 2k - 1$ and $n = \dfrac{2k - 1}{3}$. Now what? We have a fraction, and there is no obvious way to see that it is odd. We are stuck.

Now the back door. The negation of “$n$ is odd” is “$n$ is even”, which is easy to unpack.

> [!proof]
> We prove the contrapositive: if $n$ is even, then $3n + 2$ is even. Assume $n$ is even, so $n = 2k$ for some integer $k$. Then
> $$
> 3n + 2 = 3(2k) + 2 = 6k + 2 = 2(3k + 1).
> $$
> Since $3k + 1$ is an integer, $3n + 2$ is even, that is, not odd. We have shown $\neg q \to \neg p$, and therefore $p \to q$: if $3n + 2$ is odd, then $n$ is odd.

The lesson: the hypothesis “$3n + 2$ is odd” was about a **complicated** expression, while the conclusion “$n$ is odd” was about a **simple** one. Negating the simple side gave us something easy to unpack. That is the most common signal for contraposition.

### Example 2: if n² is odd, then n is odd

**Theorem.** For every integer $n$, if $n^2$ is odd, then $n$ is odd.

The front door would start with $n^2 = 2k + 1$ and then require a square root, which leads nowhere. The back door is wide open.

> [!proof]
> We prove the contrapositive: if $n$ is even, then $n^2$ is even. Assume $n$ is even, so $n = 2k$ for an integer $k$. Then $n^2 = 4k^2 = 2(2k^2)$, which is even, so it is not odd. By contraposition, if $n^2$ is odd, then $n$ is odd.

By exactly the same kind of argument (try it!), **if $n^2$ is even, then $n$ is even**. Keep this lemma in your pocket: we need it in a few minutes to prove that $\sqrt{2}$ is irrational.

### Example 3: the square-root trick behind every prime test

**Theorem.** If $n = ab$, where $a$ and $b$ are positive integers, then $a \leq \sqrt{n}$ or $b \leq \sqrt{n}$.

Here the conclusion is an “or”, and its negation is a much more useful “and”: $a > \sqrt{n}$ **and** $b > \sqrt{n}$.

> [!proof]
> We prove the contrapositive: if $a > \sqrt{n}$ and $b > \sqrt{n}$, then $n \neq ab$. Assume $a > \sqrt{n}$ and $b > \sqrt{n}$. Multiplying these two inequalities between positive numbers gives
> $$
> ab > \sqrt{n} \cdot \sqrt{n} = n,
> $$
> so $ab \neq n$. By contraposition, if $n = ab$, then $a \leq \sqrt{n}$ or $b \leq \sqrt{n}$.

> [!industry] Why this tiny theorem saves billions of steps
> If $n$ has a divisor other than 1 and itself, then by the theorem it has one that is at most $\sqrt{n}$. So a program that tests whether $n$ is prime never needs to try divisors larger than $\sqrt{n}$:
> ```python
> from math import isqrt
>
> def is_prime(n):
>     if n < 2:
>         return False
>     for d in range(2, isqrt(n) + 1):   # the theorem says this is enough
>         if n % d == 0:
>             return False
>     return True
> ```
> For $n = 1\,000\,000\,007$ that is about 31,600 divisions instead of a billion. The loop is correct **because** of the proof above; without the proof, stopping at $\sqrt{n}$ would just be a guess.

> [!warning] Contrapositive, not converse
> The contrapositive of $p \to q$ is $\neg q \to \neg p$. The **converse** is $q \to p$, and it is a different statement that may be false. “If $n$ is odd, then $3n + 2$ is odd” happens to be true too, but proving it would **not** prove our theorem. This is the fallacy of affirming the conclusion from [week 6](/weeks/week-06) in disguise.

## Proof by contradiction

Proof by contradiction is the detective’s method. A good detective says: “Suppose the butler did it. Then he was in the library at nine. But at nine he was on camera in the kitchen. He cannot be in two places at once, so the butler did not do it.” You **assume the opposite** of what you want to prove, follow the consequences honestly, and wait until they crash into something impossible.

Logically, it works because a true statement cannot imply a false one. If assuming $\neg q$ leads to a contradiction such as $r \land \neg r$, then $\neg q$ must be false, and so $q$ is true:

$$
(\neg q \to \mathbf{F}) \;\equiv\; q.
$$

The Latin name is *reductio ad absurdum*, “reduction to the absurd”.

> [!tip] Recipe for a proof by contradiction
> 1. Write “Suppose, for the sake of contradiction, that $q$ is false.”
> 2. Write down exactly what that assumption gives you.
> 3. Reason until you reach a contradiction: two statements that cannot both be true.
> 4. Write “This is a contradiction, so $q$ is true.”

### Example 1: twenty-two days

**Theorem.** If you choose any 22 days from the calendar, at least 4 of them fall on the same day of the week.

> [!proof]
> Suppose, for the sake of contradiction, that no day of the week appears 4 or more times among the 22 days. Then each of the 7 days of the week appears **at most** 3 times, so there are at most $7 \cdot 3 = 21$ days in total. But we chose 22 days. A set cannot have both 22 and at most 21 elements, so this is a contradiction. Therefore at least 4 of the days fall on the same day of the week.

This is the first appearance of the **pigeonhole principle**, which we will meet properly in the counting weeks: if you put more than $7 \cdot 3$ pigeons into 7 holes, some hole gets at least 4.

### Example 2: √2 is irrational

This is one of the most famous proofs ever written, and it is a perfect example of a statement that you **cannot** attack directly. “Irrational” means “not rational”: it is a negative statement, and there is nothing to unpack. But if we assume the opposite, that $\sqrt{2}$ **is** rational, the definition hands us two integers to work with.

One small fact first. Every fraction can be reduced to **lowest terms**, where the numerator and denominator have no common factor except 1: for example $\frac{6}{4} = \frac{3}{2}$.

**Theorem.** $\sqrt{2}$ is irrational.

> [!proof]
> Suppose, for the sake of contradiction, that $\sqrt{2}$ is rational. Then $\sqrt{2} = \dfrac{a}{b}$ for some integers $a$ and $b \neq 0$, and we may choose the fraction in lowest terms, so that $a$ and $b$ have no common factor.
>
> 1. Squaring both sides gives $2 = \dfrac{a^2}{b^2}$, so $a^2 = 2b^2$.
> 2. So $a^2$ is two times an integer: $a^2$ is even.
> 3. By our lemma (if $n^2$ is even, then $n$ is even), $a$ is even. Write $a = 2c$ for an integer $c$.
> 4. Substituting into step 1: $(2c)^2 = 2b^2$, so $4c^2 = 2b^2$, so $b^2 = 2c^2$.
> 5. So $b^2$ is even, and by the same lemma, $b$ is even.
> 6. Now $a$ and $b$ are both even, so 2 is a common factor of $a$ and $b$.
>
> But we chose $a$ and $b$ with no common factor. This is a contradiction, so $\sqrt{2}$ is irrational.

Take a moment to appreciate what just happened. We proved that **no** fraction, among the infinitely many fractions that exist, squares to exactly 2, and we did it without checking a single one. According to an old legend, the Pythagoreans were so disturbed by this discovery that they tried to keep it secret.

### Example 3: there are infinitely many primes

**Theorem** (Euclid, about 300 BC). There are infinitely many prime numbers.

“Infinitely many” is another statement with nothing to grab. Its opposite, “there are only finitely many primes”, gives us a **list** to play with.

> [!proof]
> Suppose, for the sake of contradiction, that there are only finitely many primes, and list all of them: $p_1, p_2, \dots, p_n$. Consider the number
> $$
> N = p_1 \cdot p_2 \cdots p_n + 1.
> $$
> $N$ is bigger than 1, so it has at least one prime factor $p$. Since our list contains every prime, $p$ is one of $p_1, \dots, p_n$, so $p$ divides the product $p_1 p_2 \cdots p_n$. It also divides $N$. So $p$ divides the difference $N - p_1 p_2 \cdots p_n = 1$. But no prime divides 1. This contradiction shows that the list cannot be complete: there are infinitely many primes.

> [!warning] A popular misreading
> The proof does **not** say that $N$ itself is prime. Take the first six primes: $2 \cdot 3 \cdot 5 \cdot 7 \cdot 11 \cdot 13 + 1 = 30031 = 59 \cdot 509$, which is not prime. What the proof says is that $N$’s prime factors (here 59 and 509) are missing from the list. That is all we need.

### Contraposition or contradiction?

The two indirect methods are close cousins, and students often mix them up.

| | Proof by contraposition | Proof by contradiction |
|---|---|---|
| To prove | $p \to q$ | any statement $q$ (often $p \to q$) |
| You assume | $\neg q$ | $\neg q$ (and $p$, if there is one) |
| You aim for | exactly $\neg p$ | **any** contradiction at all |
| Feels like | going in through the back door | setting a trap and waiting for it to snap |
| Best for | complicated hypothesis, simple conclusion | “there is no …”, “irrational”, “infinitely many” |

> [!tip] Tidy up after yourself
> If you wrote a proof by contradiction and the contradiction you reached was simply $\neg p$, then what you really wrote is a proof by contraposition. Rewrite it that way: it will be shorter and clearer.

## If and only if: two proofs in one

A biconditional $p \leftrightarrow q$ is a two-way street. Showing that you can drive from $p$ to $q$ says nothing about the return trip. Since

$$
p \leftrightarrow q \;\equiv\; (p \to q) \land (q \to p),
$$

the proof always has **two parts**, usually labelled $(\Rightarrow)$ and $(\Leftarrow)$. Each part is an ordinary conditional, and each may use a different technique.

**Theorem.** For every integer $n$: $n$ is odd if and only if $n^2$ is odd.

> [!proof]
> Let $n$ be an arbitrary integer.
>
> $(\Rightarrow)$ If $n$ is odd, then $n^2$ is odd. This is Example 2 of the direct proofs.
>
> $(\Leftarrow)$ If $n^2$ is odd, then $n$ is odd. This is Example 2 of the contraposition proofs.
>
> Both directions hold, so $n$ is odd if and only if $n^2$ is odd.

Notice how the proof reuses results we already have, exactly as good code calls existing functions instead of copying them. When a theorem says that **several** statements are equivalent (“the following are equivalent: $p_1, p_2, p_3$”), it is enough to prove a cycle such as $p_1 \to p_2 \to p_3 \to p_1$; you can then travel from any statement to any other.

## Where proofs go wrong

Reading a proof critically is the mathematical version of code review. Here is a classic “proof” that $1 = 2$. Every step looks innocent. Find the bug before you read the answer.

| Step | Statement | Reason given |
|---|---|---|
| 1 | $a = b$ | premise ($a$ and $b$ are equal positive integers) |
| 2 | $a^2 = ab$ | multiply both sides of 1 by $a$ |
| 3 | $a^2 - b^2 = ab - b^2$ | subtract $b^2$ from both sides of 2 |
| 4 | $(a - b)(a + b) = b(a - b)$ | factor both sides of 3 |
| 5 | $a + b = b$ | divide both sides of 4 by $a - b$ |
| 6 | $2b = b$ | replace $a$ by $b$ in 5, using 1 |
| 7 | $2 = 1$ | divide both sides of 6 by $b$ |

<details>
<summary>Where is the bug?</summary>

Step 5. Since $a = b$, the number $a - b$ is **zero**, and dividing by zero is not allowed. Steps 1 to 4 are fine: both sides of step 4 are equal to 0. Step 5 throws away that information and creates a false equation. Step 7 is fine, because $b \neq 0$.

Division by a quantity that might be zero is one of the most common errors in algebraic proofs, and one of the most common runtime errors in programs. Whenever you divide, ask: **can this be zero?**
</details>

A few other mistakes appear again and again:

- **Proof by example.** “It works for $n = 1, 2, 3$, so it works for all $n$.” Remember $n^2 + n + 41$.
- **Proving the converse.** Asked to prove $p \to q$, you assume $q$ and reach $p$. That is the fallacy of affirming the conclusion.
- **Circular reasoning** (begging the question). Somewhere in the middle, the proof uses the very statement it is trying to prove, perhaps in a slightly different wording.
- **Hidden assumptions.** “Without loss of generality, $x$ is positive,” when $x$ could perfectly well be negative.
- **Reusing a letter.** “$m = 2k$ and $n = 2k$”, which assumes that $m = n$.

## Proof by cases

Some statements are hard to prove all at once but easy to prove in pieces. An integer is even **or** odd; a real number is positive, zero **or** negative; of two numbers, one is the larger. If the statement holds in every piece, and the pieces cover everything, the statement holds. Logically, we use the tautology

$$
\big((p_1 \lor p_2 \lor \dots \lor p_n) \to q\big) \;\equiv\; \big((p_1 \to q) \land (p_2 \to q) \land \dots \land (p_n \to q)\big).
$$

A programmer can think of an `if` / `elif` / `else` chain. Each branch is a case, and each must be handled correctly. And just as code with an unhandled branch has a bug, **a proof with a missing case is not a proof**. Before you start, always check that your cases really cover every possibility.

### Example 1: n² + n is always even

**Theorem.** For every integer $n$, $n^2 + n$ is even.

> [!proof]
> Let $n$ be an arbitrary integer. Every integer is even or odd, so there are two cases.
>
> **Case 1: $n$ is even.** Then $n = 2k$ for an integer $k$, and $n^2 + n = 4k^2 + 2k = 2(2k^2 + k)$, which is even.
>
> **Case 2: $n$ is odd.** Then $n = 2k + 1$, and $n^2 + n = (4k^2 + 4k + 1) + (2k + 1) = 4k^2 + 6k + 2 = 2(2k^2 + 3k + 1)$, which is even.
>
> The two cases cover every integer, so $n^2 + n$ is even for every integer $n$.

(There is also a slicker proof: $n^2 + n = n(n + 1)$, a product of two consecutive integers, one of which must be even. Many theorems have several proofs, and finding a second one is a great way to understand the first.)

### Example 2: max is associative

Let $a \mathbin{@} b = \max(a, b)$, the larger of the two numbers. We want to show that for all real numbers $a, b, c$,

$$
(a \mathbin{@} b) \mathbin{@} c = a \mathbin{@} (b \mathbin{@} c).
$$

Three real numbers can be ordered in six ways, so we have six cases. The table works through all of them; in each case, both sides turn out to be the largest of the three numbers.

| Case | $a \mathbin{@} b$ | $(a \mathbin{@} b) \mathbin{@} c$ | $b \mathbin{@} c$ | $a \mathbin{@} (b \mathbin{@} c)$ |
|---|---|---|---|---|
| $a \geq b \geq c$ | $a$ | $a$ | $b$ | $a$ |
| $a \geq c \geq b$ | $a$ | $a$ | $c$ | $a$ |
| $b \geq a \geq c$ | $b$ | $b$ | $b$ | $b$ |
| $b \geq c \geq a$ | $b$ | $b$ | $b$ | $b$ |
| $c \geq a \geq b$ | $a$ | $c$ | $c$ | $c$ |
| $c \geq b \geq a$ | $b$ | $c$ | $c$ | $c$ |

In every row, the third and fifth columns agree: both sides equal the largest of the three numbers. So the operation is associative. This matters in practice: because `max` is associative, a database or a parallel program can compute the maximum of a billion numbers in any grouping, on many machines at once, and still get the same answer.

### Example 3: without loss of generality

**Theorem.** If $x$ and $y$ are integers and both $xy$ and $x + y$ are even, then both $x$ and $y$ are even.

This one combines two techniques. The conclusion “both are even” is simple to negate, so we use contraposition, and the negation splits naturally into cases.

> [!proof]
> We prove the contrapositive: if $x$ and $y$ are **not both** even, then $xy$ is odd or $x + y$ is odd. Assume that at least one of $x$ and $y$ is odd. **Without loss of generality**, let $x$ be odd, so $x = 2m + 1$ for an integer $m$.
>
> **Case 1: $y$ is even**, say $y = 2n$. Then $x + y = 2m + 1 + 2n = 2(m + n) + 1$ is odd.
>
> **Case 2: $y$ is odd**, say $y = 2n + 1$. Then $xy = (2m + 1)(2n + 1) = 4mn + 2m + 2n + 1 = 2(2mn + m + n) + 1$ is odd.
>
> In both cases, $xy$ or $x + y$ is odd, which proves the contrapositive.

The phrase **without loss of generality** (WLOG) means: “there is another case, but it is the same argument with the names swapped, so we do not write it twice”. Here, the case “$y$ is odd” is exactly the case “$x$ is odd” with $x$ and $y$ exchanged. Use WLOG only when the situation really is symmetric; otherwise it is a hidden assumption.

### Exhaustive proof

When there are only a few cases, you can simply check them all. This is the **one** situation where “I tried every example” is a valid proof: the examples are **all** of the cases.

**Theorem.** $(n + 1)^3 \geq 3^n$ for $n = 1, 2, 3, 4$.

| $n$ | $(n+1)^3$ | $3^n$ | holds? |
|---|---|---|---|
| 1 | 8 | 3 | ✓ |
| 2 | 27 | 9 | ✓ |
| 3 | 64 | 27 | ✓ |
| 4 | 125 | 81 | ✓ |

All four cases hold, so the theorem is proved. But look what happens at $n = 5$: $6^3 = 216$ and $3^5 = 243$. The inequality fails. That is why the theorem is stated only for $n \leq 4$, and why an exhaustive proof proves exactly the cases it checks, not one more.

> [!industry] When the cases are too many for humans
> In 1976, Kenneth Appel and Wolfgang Haken proved the **four colour theorem** (every map can be coloured with four colours so that neighbouring countries differ) by reducing it to almost two thousand cases and letting a computer check each one. It was the first major theorem proved with the help of a computer, and mathematicians argued for years about whether it counted. Today, proofs that combine human reasoning with computer case-checking are routine, in mathematics and in chip verification alike.

## Existence proofs: show me one

A statement of the form $\exists x\, P(x)$ asks for much less than a universal one: **one** witness is enough.

### Constructive: here it is

The most satisfying existence proof simply hands you the object.

**Theorem.** There is a positive integer that can be written as a sum of two cubes of positive integers in two different ways.

> [!proof]
> The number 1729 works: $1729 = 10^3 + 9^3 = 12^3 + 1^3$. By existential generalization, such an integer exists.

There is a lovely story behind this number. The mathematician G. H. Hardy visited Srinivasa Ramanujan in hospital and remarked that his taxi’s number, 1729, seemed rather dull. Ramanujan immediately replied that it was very interesting: the smallest number expressible as a sum of two cubes in two different ways. Ever since, 1729 has been called the **taxicab number**.

### Nonconstructive: it is in one of these two drawers

Sometimes you can prove that something exists without being able to point at it. Imagine knowing for certain that your keys are in one of two drawers, without knowing which one. You do not know where they are, but you know **that** they are somewhere.

**Theorem.** There are irrational numbers $x$ and $y$ such that $x^y$ is rational.

> [!proof]
> We know that $\sqrt{2}$ is irrational. Consider the number $\sqrt{2}^{\sqrt{2}}$. It is either rational or irrational.
>
> **Drawer 1: $\sqrt{2}^{\sqrt{2}}$ is rational.** Then $x = \sqrt{2}$ and $y = \sqrt{2}$ work.
>
> **Drawer 2: $\sqrt{2}^{\sqrt{2}}$ is irrational.** Then take $x = \sqrt{2}^{\sqrt{2}}$ and $y = \sqrt{2}$. Both are irrational, and
> $$
> x^y = \Big(\sqrt{2}^{\sqrt{2}}\Big)^{\sqrt{2}} = \sqrt{2}^{\sqrt{2} \cdot \sqrt{2}} = \sqrt{2}^{\,2} = 2,
> $$
> which is rational.
>
> In either case, suitable $x$ and $y$ exist.

The proof never tells us which drawer is the right one, and it does not need to. (Much harder mathematics, the Gelfond–Schneider theorem of 1934, shows that $\sqrt{2}^{\sqrt{2}}$ is in fact irrational, so drawer 2 is the right one.)

> [!note] Uniqueness
> Sometimes a theorem says there is **exactly one** $x$ with a property. Such a proof has two parts: **existence** (show that some $x$ works) and **uniqueness** (show that if $x$ and $y$ both work, then $x = y$). For example, if $a \neq 0$, the equation $ax + b = 0$ has the solution $x = -b/a$; and if $ax + b = 0$ and $ay + b = 0$, then $ax = ay$, so $x = y$.

## Counterexamples: one is enough

We end where we began. To show that a universal statement $\forall x\, P(x)$ is **false**, we do not need a long argument. By De Morgan’s law for quantifiers from [week 4](/weeks/week-04),

$$
\neg \forall x\, P(x) \;\equiv\; \exists x\, \neg P(x),
$$

so all we need is **one** $x$ for which $P(x)$ fails. Such an $x$ is called a **counterexample**. This is the asymmetry at the heart of the whole week:

- To prove “for all”, you need an argument that covers every case.
- To disprove “for all”, you need just one case.

**Claim.** Every positive integer is the sum of the squares of three integers.

It starts well: $1 = 1^2 + 0^2 + 0^2$, $2 = 1^2 + 1^2 + 0^2$, $3 = 1^2 + 1^2 + 1^2$, $4 = 2^2 + 0^2 + 0^2$, $5 = 2^2 + 1^2 + 0^2$, $6 = 2^2 + 1^2 + 1^2$. But $7$ is a counterexample. The only squares that do not exceed 7 are 0, 1 and 4, and no three of them (repetitions allowed) add up to 7: using a 4 leaves 3 to be made from two of $\{0, 1\}$, which is impossible, and without a 4 the most you can reach is $1 + 1 + 1 = 3$. So the claim is false.

> [!industry] Two hundred years, then two sentences
> In 1769 Leonhard Euler conjectured that you need at least $k$ $k$-th powers to add up to another $k$-th power (at least three cubes, at least four fourth powers, at least five fifth powers, and so on). Nobody could prove it or break it for almost two centuries. In 1966, L. J. Lander and T. R. Parkin ran a computer search and found
> $$
> 27^5 + 84^5 + 110^5 + 133^5 = 144^5,
> $$
> four fifth powers whose sum is a fifth power. Their paper, one of the shortest in the history of mathematics, is essentially that one line. Today, **property-based testing** tools such as Python’s Hypothesis bring the same idea to everyday code: you state a property that should hold for all inputs, and the tool hunts for a counterexample and shrinks it to the smallest one it can find.

Remember the other side of the coin, too. Computers have checked Goldbach’s conjecture (every even number greater than 2 is a sum of two primes) for every even number up to $4 \times 10^{18}$, and it has never failed. It is still called a conjecture, because a search, however long, checks only finitely many cases. A proof is still missing.

## Choosing a technique

This is the question students ask most often: **how do I know which method to use?** There is no algorithm that always works (in fact, there provably cannot be one, a story for a later course). But the **shape** of the statement gives strong hints. Click on the shape that matches your statement:

<ProofChooser id="chooser-week7" />

And when you are not sure, follow this order:

1. **Write down the definitions** of every word in the statement.
2. **Try a few small examples**, to understand why the statement might be true, and to catch it if it is false.
3. **Try a direct proof.** Unpack, work, repack.
4. If you get stuck because the hypothesis is hard to use, **try the contrapositive**.
5. If the statement is negative (“no …”, “irrational”, “infinitely many”), **try contradiction**.
6. If the objects split naturally into kinds, **try cases**.

### Working backwards

Last week we planned the lake argument by starting from the goal and asking “what would give me this?”. The same trick, **backward reasoning**, is one of the most powerful tools for finding proofs.

**Theorem.** For distinct positive real numbers $x$ and $y$, the arithmetic mean is larger than the geometric mean:
$$
\frac{x + y}{2} > \sqrt{xy}.
$$

There is no obvious place to start. So start from the end and ask, at each step, “what would be enough to give me this?”

- $\dfrac{x + y}{2} > \sqrt{xy}$ would follow from $\dfrac{(x + y)^2}{4} > xy$ (both sides are positive, so we may square),
- which would follow from $(x + y)^2 > 4xy$,
- which is $x^2 + 2xy + y^2 > 4xy$,
- which is $x^2 - 2xy + y^2 > 0$,
- which is $(x - y)^2 > 0$.

And **that** is certainly true, because $x \neq y$ and the square of a nonzero number is positive. We have found the road; now we drive it forwards to write the proof.

> [!proof]
> Since $x \neq y$, we have $(x - y)^2 > 0$, so $x^2 - 2xy + y^2 > 0$. Adding $4xy$ to both sides gives $(x + y)^2 > 4xy$, and dividing by 4 gives $\dfrac{(x + y)^2}{4} > xy$. Both $\dfrac{x + y}{2}$ and $\sqrt{xy}$ are positive, so taking square roots keeps the inequality: $\dfrac{x + y}{2} > \sqrt{xy}$.

Backward reasoning is how you **find** a proof; forward reasoning is how you **write** it. Never hand in the backward version on its own: “the conclusion leads to something true” is affirming the conclusion again.

### A game you can always win

**Theorem.** Two players take turns removing 1, 2 or 3 stones from a pile that starts with 15 stones. Whoever takes the last stone wins. The first player can always win, whatever the second player does.

Think backwards from the end of the game. To take the last stone, you want your opponent to face a pile of **4**: whatever they take (1, 2 or 3), you take the rest. To force them to face 4, you want them to face **8**: whatever they take, you take enough to make the total for the round 4, leaving 4. By the same reasoning, you want them to face **12**.

> [!proof]
> The first player takes 3 stones, leaving 12. From then on, whenever the second player takes $t$ stones ($t \in \{1, 2, 3\}$), the first player takes $4 - t$ stones, which is also between 1 and 3. Each full round removes exactly 4 stones, so the second player faces 12, then 8, then 4 stones. Facing 4, the second player must leave 1, 2 or 3 stones, and the first player takes them all and wins.

This “work backwards from the end” idea is exactly how game-playing programs reason about winning positions, and it will come back when we study recursion.

### A puzzle about dominoes

Can you cover a standard $8 \times 8$ chessboard with dominoes, each covering two neighbouring squares, with no overlaps and nothing sticking out? **Yes**, and the proof is constructive: place four dominoes side by side in every row. Now remove squares.

<Checkerboard />

- **One corner removed.** No tiling is possible, by a counting argument. The board has 63 squares, and every tiling covers an **even** number of squares (two per domino). 63 is odd.
- **Two opposite corners removed.** Now there are 62 squares, an even number, so counting does not help. Try it on paper and you will keep failing, but failing is not a proof. Here is one, using **colours**. Every domino covers one dark and one light square, so any tiling covers equally many squares of each colour. The two removed corners have the **same** colour (here both dark), so the board has 30 dark and 32 light squares. Equal numbers are impossible, so no tiling exists.

The colouring is what mathematicians call an **invariant**: a quantity that every move preserves. Invariants are among the most elegant proof tools there are, and they are also how programmers argue that a loop is correct (“at the start of every iteration, this property holds”).

## How to write a proof that others can read

A proof is written for a reader, not for yourself. A few habits make an enormous difference:

- **Say what you are proving and how.** “We prove the contrapositive.” “Suppose, for contradiction, that …”
- **Introduce every variable** before you use it: “Let $n$ be an arbitrary integer.” “… for some integer $k$.”
- **Justify every step.** Name the definition, the lemma or the algebra you are using.
- **Write in sentences.** Symbols are for formulas; the logic between them (“so”, “therefore”, “since”, “in both cases”) belongs in words.
- **Say when you are done.** End with the conclusion stated in full, and mark it with ∎ (or QED, *quod erat demonstrandum*, “which was to be shown”).

And when you read someone else’s proof, read it like a code reviewer: check every step, and ask “why does this line follow?” Your own proofs deserve the same treatment.

## Summary

A proof is a valid argument that establishes the truth of a statement from axioms, definitions and earlier theorems. Examples can make a statement plausible but can never prove a claim about infinitely many cases, while a single counterexample is enough to disprove a universal claim. Most proofs follow the rhythm **unpack, work, repack**, built on definitions such as even, odd, rational and divides.

To prove $p \to q$: a **direct proof** assumes $p$ and derives $q$; **contraposition** assumes $\neg q$ and derives $\neg p$, useful when the hypothesis is awkward and the conclusion simple; **contradiction** assumes the statement is false and derives something impossible, ideal for statements such as “$\sqrt{2}$ is irrational” and “there are infinitely many primes”. A **biconditional** needs both directions. **Proof by cases** splits the domain into pieces that cover everything; an **exhaustive proof** checks every case of a finite domain. **Existence proofs** can be constructive (exhibit a witness) or nonconstructive (show a witness must exist). When you are stuck, write down the definitions, try small examples, and reason **backwards** from the goal to find the path, then write it forwards.

1. Let $n = 2k + 1$. Then $n^3 = 8k^3 + 12k^2 + 6k + 1 = 2(4k^3 + 6k^2 + 3k) + 1$, which is odd.
