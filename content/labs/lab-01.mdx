<Step n={4} title="Part A: the connectives" time="10 min" id="part-a">

Open `truth.py`. Python has `not`, `and` and `or`. Write `implies`, `iff` and `xor`. Replace each `raise NotImplementedError` with a `return` statement.

Use the lecture: $p \to q$ is false **only** when $p$ is true and $q$ is false, so it equals $\neg p \lor q$. For booleans, $p \leftrightarrow q$ is “same value” and $p \oplus q$ is “different value”.

<Terminal cmd="python check.py" out={`:) implies(p, q) matches the truth table of p → q
:) iff(p, q) matches the truth table of p ↔ q
:) xor(p, q) matches the truth table of p ⊕ q`} />

</Step>

<Step n={5} title="Part B: every row" time="10 min" id="part-b">

`rows(n)` returns every assignment of `n` variables as a list of tuples, `True` before `False`, the last variable changing fastest. For two variables:

```python
rows(2) == [(True, True), (True, False), (False, True), (False, False)]
```

`itertools.product` (already imported) does exactly this. Try it in the terminal first:

<Terminal cmd={'python -c "from itertools import product; print(list(product([True, False], repeat=2)))"'} />

Watch out: `product` returns an iterator, and the function must return a **list**. And what should `rows(0)` be? One row with no variables, `[()]`. Check that `product` agrees.

</Step>

<Step n={6} title="Part C: tables and verdicts" time="20 min" id="part-c">

A formula is a Python function. For example `lambda p, q: implies(p, q)` takes two booleans and returns one. To evaluate it on a row (a tuple), unpack the tuple: `f(*row)`.

Write, in this order, reusing each function in the next:

1. `truth_table(f, n)`: a list of `(row, f(*row))` pairs, for every row of `rows(n)`.
2. `is_tautology`: true in **every** row. Python's `all()` is ∀.
3. `is_satisfiable`: true in **at least one** row. Python's `any()` is ∃. (You will meet ∀ and ∃ again in [week 4](/weeks/week-04).)
4. `is_contradiction`: true in **no** row.
5. `equivalent(f, g, n)`: same value in every row.
6. `count_true(f, n)`: how many rows are true.

> [!try] Think before you code
> Can you write `is_contradiction` in one line using `is_satisfiable`? Can you write `equivalent` using `is_tautology` and `iff`?

</Step>

<Step n={7} title="Part D: pretty printing" time="10 min" id="part-d">

`format_table(f, names, label)` returns the table as **one string**. The format must match exactly, because the autograder compares strings:

```text
p q | p∧q
1 1 | 1
1 0 | 0
0 1 | 0
0 0 | 0
```

Values separated by one space, the result after `" | "`, lines joined with `"\n"`, no trailing newline. Tips: `" ".join(...)`, and `"1" if v else "0"`.

Then run the demo at the bottom of the file:

<Terminal cmd="python truth.py" out={`p q | p→q
1 1 | 1
1 0 | 0
0 1 | 1
0 0 | 1

(p → q) ↔ (¬q → ¬p) is a tautology: True
(p → q) ↔ (q → p)   is a tautology: False`} />

You just proved, by exhaustion, that the contrapositive is equivalent and the converse is not.

</Step>

<Step n={8} title="Part E: English to Python" time="10 min" id="part-e">

Let $p$: “the server is overloaded”, $q$: “the request is served from cache”, $r$: “the response is slow”. Translate each sentence into a Python expression over `p`, `q`, `r`. You may use your own `implies`.

1. `spec1`: The response is slow **only if** the server is overloaded and the request is not served from cache.
2. `spec2`: The request is served from cache **unless** the server is overloaded.
3. `spec3`: **Neither** is the server overloaded **nor** is the response slow.

These are the translation exercises from the lecture. If a check fails, look at the week 2 notes on “only if” and “unless”.
